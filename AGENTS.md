# AGENTS.md — правила для ИИ-агентов в репозитории `flowreader`

FlowReader — читалка для Android на Flutter: PDF (через закрытый конвертер), EPUB и FB2 импортируются в единый
формат блоков, свой рендер с листанием «как живая книга». Всё работает на устройстве.
Этот репозиторий публичный (GPL-3.0-only): Flutter-приложение + открытый Rust (`rust/flow-core`, `rust/bridge`).
Закрытый конвертер PDF живёт в отдельном приватном репозитории `flowreader-converter` и сюда не копируется.

Правила обязательны для любого агента (Claude Code, Codex, Cursor и т. д.). Нарушение правила допустимо только
по явному решению человека в чате.

---

## 1. Как работаем

1. **Гриллинг задачи** — вопросы человеку по одному, пока нет общего понимания.
2. **Спека** — короткий документ с решениями. **Подтверждает человек.** Без подтверждённой спеки код не пишется.
3. **Разбиение** спеки на маленькие задачи.
4. **Реализация** задач по очереди в ветке задачи: `feat/…`, `fix/…`, `docs/…`, `chore/…`, `refactor/…`, `test/…`.
5. **Круг «ревью → QA → исправления»**, пока чисто:
   - ревью — агент сам, по чек-листу «готово» (раздел 8), по диффу ветки;
   - QA — автоматика (тесты, линтеры, CI) + прогон на Pixel 7 по сценариям спеки; скриншоты и короткий отчёт в PR.
6. **Человек тестирует сам, делает ручное ревью PR и мержит в `main`.**

Внутри утверждённой спеки агент работает сам. **Обязан остановиться и спросить человека**, если:
- нужна новая зависимость (пакет, крейт, инструмент);
- меняется формат блоков (`flow_core::model`), API импорта (`flow_core::import`), API моста или схема БД;
- меняется граница между открытым и закрытым кодом;
- задача выходит за рамки спеки или требует отступить от этих правил.

Общение с человеком: коротко, простым языком, один вопрос за раз, с рекомендацией.
Без субагентов (см. `CLAUDE.md`).

### Git
- Задача = ветка = PR в `main`. `main` защищён: прямые коммиты и push в `main` запрещены; мерж — только человек.
- Коммиты — Conventional Commits на английском: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`.
- История не переписывается (`rebase`, `commit --amend`, `squash`, `reset` опубликованных коммитов, `push --force`) —
  **только с явного разрешения человека в чате.** Склейку делает человек кнопкой «Squash and merge».
- push — только в ветку своей задачи.
- Хук перед коммитом подключается один раз: `git config core.hooksPath .githooks`. Обходить его (`--no-verify`) запрещено.

## 2. Архитектура и границы

### 2.1 Код в репозитории
```
lib/                 Flutter-приложение (MVVM, см. 2.2)
rust/flow-core/      открытое ядро: формат блоков, кодек, переносы, импорт EPUB/FB2, экспорт EPUB
rust/bridge/         мост flutter_rust_bridge (Cargo-пакет `rust_lib_flowreader`); заглушка конвертера PDF
rust_builder/        cargokit (сборка Rust для Flutter), не править без причины
docs/                спеки, решения, отчёты проверок
```
- Открытая сборка собирается и работает без закрытого конвертера.
- Контракт с конвертером — только формат блоков (`flow_core::model`, версионируется, эталонный фикстур
  `rust/flow-core/tests/fixtures/book_v1.cbor`) и трейт `Converter` / API импорта. Их изменение — вопрос человеку
  и повышение `FORMAT_VERSION`.

### 2.2 Flutter: MVVM по руководству Flutter (docs.flutter.dev/app-architecture), ViewModel и DI на Riverpod
```
lib/
├── ui/<функция>/view_models/   ViewModel = Riverpod Notifier / AsyncNotifier (кодогенерация @riverpod)
├── ui/<функция>/widgets/       View: только отображение
├── ui/core/                    общие виджеты, тема
├── domain/models/              неизменяемые модели (freezed)
├── domain/use_cases/           только если логика повторяется в нескольких ViewModel или сложна
├── data/repositories/          источник правды по типу данных; абстрактный класс + реализация
├── data/services/              обёртки над источниками (Drift, Rust-мост, файлы, платформа); без состояния
├── utils/                      чистые утилиты без Flutter
├── routing/                    go_router
├── config/                     провайдеры зависимостей, окружение
└── l10n/                       ARB-локализация (ru, en)
```
Правила:
- View ↔ ViewModel — один к одному. В виджетах нет логики (допустимо: показать/скрыть, анимация, раскладка,
  простая навигация).
- ViewModel не импортирует Flutter-виджеты и не обращается к Service напрямую — только к Repository или use-case.
- Repository не знают друг о друге; объединение данных двух репозиториев — во ViewModel или use-case.
- Service без состояния, один на источник данных. Доступ к Rust — только через `RustCoreService`;
  сгенерированный код моста (`lib/src/rust/**`) не импортируется из `ui/` и `domain/`.
- Однонаправленный поток: данные вверх (Stream / модели), события вниз (методы ViewModel).
- Зависимости — только через провайдеры Riverpod; никаких глобальных синглтонов.
- Направления импортов: `domain` ↛ `ui`, `data`; `data` ↛ `ui`. Проверяется линтером.
- Имена по роли: `ReaderScreen`, `ReaderViewModel`, `BookRepository`, `RustCoreService`.
- Пакет рендера (вёрстка, разбивка на страницы, шейдер листания) — отдельный пакет в репозитории, без Riverpod.

### 2.3 Rust
```
rust/flow-core/src/
├── lib.rs        только объявление модулей и реэкспорт публичного API
├── model/        формат книги: book, block, inline, resource — ни от чего не зависит
├── codec/        CBOR encode/decode, проверка версии — зависит от model
├── text/         обработка текста: переносы, нормализация
├── import/       api (Converter, Progress, ImportError, CancelToken, SourceKind), stub, epub/, fb2/
└── export/       экспорт в EPUB
rust/flow-core/tests/          интеграционные тесты по модулям + fixtures/
rust/flow-core/dictionaries/   данные переносов + NOTICE.md
```
- Зависимости модулей только вниз: `import`/`export` → `model`, `text`; `codec` → `model`; `model` → ничего. Без циклов.
- `flow-core`: без ввода-вывода по путям и без платформенного кода — только логика и форматы.
- `bridge`: тонкий слой API для Dart; логика — в `flow-core`, не в мосте.
- Конвертер получает исходник только как байты / дескриптор файла, без путей.

## 3. Общие принципы кода (Rust и Dart)

- **DRY:** у каждого знания одно место в коде.
- **SOLID:**
  - **S** — одна ответственность: модуль/класс/функция меняется по одной причине;
  - **O** — расширяем без правки готового (новый формат импорта = новая реализация, а не `if kind == …` по коду);
  - **L** — любая реализация абстракции (Repository, `Converter`, фейк в тестах) взаимозаменяема;
  - **I** — узкие интерфейсы: зависим только от того, что используем;
  - **D** — зависим от абстракций; конкретику подставляют провайдеры Riverpod / конструктор.
- **Сначала ищем готовое.** Перед написанием функции, виджета, типа, утилиты или хелпера — поиск по репозиторию
  и по уже подключённым зависимостям (стандартная библиотека, используемые пакеты/крейты). Есть подходящее —
  используем или расширяем.
- **Не копируем код.** Одинаковая или почти одинаковая логика во втором месте выносится в общее:
  Rust — модуль `flow-core` / общий `util`-модуль крейта; Dart — `lib/utils/`, `lib/ui/core/`, `lib/domain/`;
  тесты — `test/helpers/`, `rust/flow-core/tests/common/`.
  Исключение: код, который лишь выглядит одинаково, но меняется по разным причинам, — с комментарием «почему не общее».
- Константы и «магические числа» — именованные, в одном месте.
- Файл длиннее ~400 строк — сигнал разделить.

## 4. Rust

- **Без паники в библиотечном коде** (`flow-core`, `bridge`): `unwrap`, `expect`, `panic!`, `unreachable!`, `todo!`,
  `unimplemented!`, индексация с возможным выходом за границы — запрещены линтером (`[workspace.lints]`).
  Только `Result` с типизированными ошибками. Исключения: `#[cfg(test)]`, `tests/`, `src/bin/`, `examples/`.
  Инварианты — `debug_assert!`.
- Ошибки: свой `enum` на модуль (`thiserror`); без `String`-ошибок в публичном API.
- `cargo fmt` (умолчания), `cargo clippy --all-targets -- -D warnings`: стандартный clippy + запреты паники +
  приведения чисел (`cast_possible_truncation`, `cast_sign_loss`, `cast_precision_loss`, `cast_lossless`).
- `unsafe` — только в одном модуле на крейт, с комментарием `// SAFETY:` к каждому блоку.
- Публичный API документирован (`///`), `#![deny(missing_docs)]` в `flow-core`.
- Числа с плавающей точкой: сортировка/сравнение через `total_cmp`; `is_finite` на внешнем входе.
- Без глобального изменяемого состояния, кроме `OnceLock` для дорогих неизменяемых данных.

## 5. Dart / Flutter

- Анализатор: `very_good_analysis` + `strict-casts`, `strict-inference`, `strict-raw-types`; `flutter analyze` — 0 замечаний.
  Отключение правила — только в `analysis_options.yaml` с комментарием «почему». Сгенерированный код исключён.
- `dart format` (`--set-exit-if-changed`).
- Без `dynamic`; без `!` (null-assert) в коде приложения (кроме тестов); `late` — только с комментарием.
- Модели неизменяемые (`freezed`), изменение через `copyWith`.
- Riverpod — только кодогенерация (`@riverpod`, `riverpod_generator`) + `riverpod_lint` / `custom_lint` без замечаний.
  После изменений: `dart run build_runner build -d`; сгенерированные файлы коммитятся.
- Все строки интерфейса — ARB (`lib/l10n/app_ru.arb`, `app_en.arb`); строковых литералов в виджетах нет.
- **Один виджет — один файл.** Каждый публичный виджет — в своём файле, имя файла = имя виджета в snake_case
  (`ReaderScreen` → `reader_screen.dart`). Приватные виджеты (`_PageCorner`) в чужом файле не прячем: если виджет
  нужен больше чем одному родителю или длиннее ~30 строк — он публичный и в своём файле. То же для ViewModel:
  один ViewModel — один файл (`reader_view_model.dart`).
- Виджеты маленькие, `const`-конструкторы где возможно.
- Асинхронность: ошибки не глотаются; `AsyncValue` во ViewModel; явные состояния загрузки и ошибки на экране.

## 6. Тесты

- **TDD:** сначала тест, он обязан упасть без изменения (RED), потом код (GREEN). Тест, который проходит без
  проверяемой логики, — дефект: проверь, временно сломав правило.
- Баг-фикс начинается с теста, воспроизводящего баг.
- Юнит-тесты на каждый Service, Repository, ViewModel, use-case и модуль Rust; виджет-тесты на экраны
  (включая навигацию и подстановку зависимостей). Фейки вместо моков (провайдеры Riverpod / трейты в Rust).
- **Покрытие ≥ 85% строк** для слоёв с логикой: `rust/flow-core`, `rust/bridge`, `lib/domain`, `lib/data`,
  `lib/ui/**/view_models`, `lib/utils`. Новый код в PR — тоже ≥ 85%. Виджеты и сгенерированный код не считаются.
- Тесты быстрые и детерминированные: без сети, без реального времени, без зависимости от порядка.
  Тесты, требующие устройство/внешние файлы, помечены и пропускаются с громкой строкой `SKIPPED: …`, но
  обязательны в QA-прогоне.
- Golden-тесты — со встроенными шрифтами; эталоны генерируются в CI, не на локальной машине.

## 7. Запреты

Жёсткие:
- **Корпус книг** (файлы, текст, страницы-картинки, названия и авторы книг из корпуса) — никогда в этот репозиторий:
  ни в файлы, ни в историю, ни в сообщения коммитов.
- **Секреты** (ключи подписи, `key.properties`, `*.jks`, токены, пароли) — никогда в git.
- **Личные данные** (почта, пути вида `C:\Users\…`, имена) — не в код и документы (кроме метаданных git).
- **Лицензии:** только совместимые с GPL-3.0-only и разрешительные (MIT / Apache-2.0 / BSD / SIL OFL); новая
  зависимость — вопрос человеку; уведомления о лицензиях — в README / NOTICE.
- **Закрытый код** `flowreader-converter` сюда не копируется.
- **Разрушительные действия** (удаление файлов вне задачи, `git clean`, `reset --hard`, удаление веток, данных на
  устройстве) — только после подтверждения человеком.

Текущие решения (меняет только человек):
- Сервисы Google (Play Services, Firebase и т. п.) не используются; добавление — решение человека.
- Сборка `store` без разрешения `INTERNET`; сеть — только в сборке `github` для OTA-обновлений.

## 8. «Готово» — чек-лист перед PR

Задача
- [ ] Сделано ровно то, что в спеке/задаче; отступления согласованы с человеком.
- [ ] Тесты написаны первыми; RED → GREEN зафиксированы; новый тест падает без изменения.
- [ ] Покрытие слоёв с логикой ≥ 85%, нового кода ≥ 85%.

Автоматика (локально и в CI — всё зелёное)
- [ ] `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` (из `rust/`).
- [ ] `dart format --set-exit-if-changed .`, `flutter analyze`, `dart run custom_lint`, `flutter test`.
- [ ] Кодогенерация актуальна (`build_runner`, `flutter_rust_bridge_codegen generate`) и закоммичена.

QA
- [ ] Прогон на Pixel 7 по сценариям спеки; скриншоты и отчёт в PR (для задач с интерфейсом).

Ревью по диффу
- [ ] Архитектура и направления зависимостей (раздел 2); нет логики в виджетах; один виджет — один файл.
- [ ] DRY: искал существующие функции/утилиты/хелперы в репозитории и зависимостях; повторы вынесены в общее место.
- [ ] SOLID: одна ответственность; зависимости через абстракции; расширение без правки готового.
- [ ] Нет паники в библиотечном Rust; ошибки типизированы; нет `dynamic` / `!` в Dart.
- [ ] Нет строк интерфейса вне ARB; нет секретов, личных данных, материалов корпуса; лицензии зависимостей проверены.
- [ ] Обработаны пустые, битые и огромные входные данные там, где вход приходит извне.

PR
- [ ] Описание по шаблону `.github/pull_request_template.md`, включая решения, принятые агентом по ходу.
